# Server architecture

The implementation separates persistent tmux entities, request connections, and wire protocols. C++ owns behavior; nanobind and Node-API adapt the shared `ServerConnection`. The full product and compatibility requirements remain in [GOAL.md](../GOAL.md).

## Entities and ownership

`Server::State` owns maps of `Session`, `Window`, `WindowLink`, `Pane`, and `PaneProgram` objects, the server-global session `OptionTable`, and the ordered server-global `PasteBuffer` collection. Each `Session` owns its local option overrides and inherits missing session options from the server table. Session and window identities are allocated without reuse during the server lifetime.

`SessionEventJournal` retains at most 4096 committed facts without becoming authoritative state. Session operations append entity-local `SessionCreatedEvent`, `SessionRenamedEvent`, and `SessionClosedEvent` values only after mutation commits. `SessionEventCursor` qualifies the next record by server lifetime; discarded history returns `observation_gap` rather than fabricated continuity.

A `Session` owns indexed memberships and its selected membership. A `WindowLink` connects that session index to a shared `Window`. The window owns its pane-partition tree and panes and records all retaining memberships. Removing one membership preserves the window; removing its final membership releases its panes. Public `SessionSnapshot`, `WindowSnapshot`, and `WindowLinkSnapshot` values survive deletion.

`WindowLayout` owns left-right and top-bottom partition cells with one-cell borders and derived `PaneGeometry` leaves. Split and resize algorithms operate on a candidate tree before the window adopts it. Resizing preserves recursive pane minima and distributes same-axis cells in stable round-robin order. The selected size may clamp above a smaller client offer. `LatestClientWindowSize` applies the declared `latest` policy to the complete layout, resizes every pane PTY and terminal, and invalidates every attached client viewing that window. Other tmux size policies remain open.

A pane owns its PTY, program-input queue, terminal state, and raw-output retention. `PaneProgram` owns its direct child and pidfd separately. Pane removal closes the PTY and requests HUP. The server keeps child ownership until nonblocking reaping completes, escalating to KILL after 250 milliseconds. Explicit shutdown has a 700-millisecond bound and reports a child that outlives it. A child also receives KILL if its owning daemon dies. External collection relinquishes child ownership without inventing an exit status. Callers must leave child reaping and process-group signaling to the server.

A `PasteBuffer` owns an explicit name, arbitrary bytes, and the server revision that stored them. It is server-global and outlives any pane or client until deletion or server shutdown. Names are valid UTF-8 without control bytes and use at most 128 bytes. The current bounded store retains at most 50 names with 256 KiB per buffer. Pasting retains the buffer, maps line feeds to carriage returns, and atomically admits the resulting bytes through the destination pane's existing program-input queue.

`TerminalState` retains the libvterm parser, primary/alternate screens, cursor, rendition, and bounded history across output chunks. One UTF-8 decoder owns continuation; designated GL character sets map decoded ASCII, including after malformed bytes, independently of chunk boundaries. It owns copied snapshots and 64-KiB-bounded terminal replies. All access is serialized; C callbacks contain exceptions. A callback failure marks observations incomplete and stops later parser mutation. The default program terminal has 24 rows and 80 columns. Storage permits at most 16384 cells, 512 rows/columns, and 1000 history lines; reflow is disabled. `ClientView` composes every pane interior, basic ASCII layout borders, and the active-pane cursor from copied window state and outer-terminal dimensions. `ClientViewRefresh` decides when to compose and accepts redraw bytes into `ClientTerminal`; `ClientTerminalRouting` separately applies descriptor readiness and routes input to the selected pane. Overlays, modes, additional size policies, and capability-sensitive borders and output remain open.

`ClientKeyInput` owns one attached client's active key table and at most 64 KiB of terminal bytes awaiting a routing decision. A prefix can therefore cross descriptor-read boundaries without leaking to the pane. The immutable `KeyTableCatalog` resolves normalized keys to operation-backed bindings; the mutable `KeyBindingRegistry` exists only during startup validation. `OptionCatalog` separately owns immutable option definitions; runtime `OptionTable` values remain with their server or session owner. The initial key parser accepts `None`, one ASCII byte, and `C-a` through `C-z` for `prefix` and `prefix2`. Either effective prefix takes precedence in `root`. An unmatched prefix-table key retries `root`, then is consumed when lookup began outside `root`, matching tmux's table transition. In the prefix table, `C-b` admits the configured primary prefix through `SendPaneInput`; `"` and `%` split the selected pane; `d` detaches the client; and `o` resolves the next pane in current layout order. Binding backpressure must occur before effects: input then preserves the command key and active table for a later event-loop turn. `KeyBindingEffect::selected_pane_changed` makes `ClientTerminalRouting` resolve the current session, window, and pane again before later bytes from the same read; a one-pane `o` reports `selected_pane_unchanged`. Complete tmux key decoding, configurable key tables and bindings, repeat timers, `Any` bindings, modes, and user-defined command lists remain open.

`PaneProgramInput` admits requests atomically into a 256-KiB queue and retains write remainders across writable readiness. `Pane::advance_pty_io` owns separate 64-KiB read/write allowances shared across all nested flushes in one servicing pass. Operations admit input without writing outside that pass. Earlier terminal replies must enter the queue before later user input or output parsing. PTY failure or output EOF closes input admission. Delivery failures retain undelivered bytes and report that a delivered prefix may have taken effect. Accepted input can remain pending after operation completion.

`PaneTextSnapshot` carries server/pane ownership, a terminal parser/resize revision, screen dimensions, cursor, UTF-8 rows, history gaps, and input status. Its revision differs from server metadata revisions. Wide-cell continuations add no text spaces. The snapshot omits rendition and client composition. Its `complete` flag describes callback processing, not full VT compatibility. Terminal history and screen text cannot recover discarded raw bytes.

Raw pane bytes, retained terminal state, composed client views, queued redraws, and delivered prefixes are separate representations with separate owners and revisions. `ClientView::record_queued_redraw` advances only after `ClientTerminal` accepts the bytes; queue acceptance does not prove write completion, downstream parsing, presentation, or observation. Reattachment composes current retained state and does not claim historical replay. Client composition must not mutate pane terminal state.

## Operations and connections

Entity-local operation files implement typed requests and results. `OperationRegistry::add<Operation>()` verifies its constrained contract. Startup rejects duplicate identities, undeclared capabilities/effects, and missing or changed public descriptions before consuming the registry into an `OperationCatalog` and opening sockets. Runtime protocol code can receive only that immutable catalog. The catalog validates complete decoding before execution. A waiting operation owns a move-only continuation and deadline, allowing other connections to progress.

Stock commands have a separate typed registry. Command descriptions declare aliases and their required native operation. Startup validates those references and produces a `CommandCatalog`; accepted-client traffic cannot add registrations. Parsing, target resolution, and formatting stay outside the transport loop. `select-pane` and `selectp` resolve an exact pane target through `SelectPane`; selection invalidates views through the window revision. `set-option` and `set` accept exact `-g` or `-t target` assignments for `prefix` and `prefix2`, resolve textual targets at execution, then invoke `SetSessionOption` with a closed global-or-`SessionId` target. `set-buffer`, `paste-buffer`, and `delete-buffer` invoke the typed paste-buffer operations and reject unsupported flags before effects. The control-mode parser accepts one bounded command line with quotes and escapes, then invokes the same immutable catalog. Command queues, groups, hooks, and broader options remain open.

Key bindings use the same construction boundary without sharing the stock-command parser. Each typed binding lives beside its entity operation and declares a table, normalized key, tmux command name, and required native operation. `KeyBindingRegistry` rejects incomplete descriptions, duplicate table-key pairs, missing operation dependencies, and registration after catalog construction. Runtime input receives only `KeyTableCatalog`; no operation-specific branch exists in the terminal routing loop. A binding may request retry through `TmuxErrorCode::backpressure` only before effects.

Process CLI actions use a smaller startup registry and immutable `ActionCatalog` at the executable boundary. `CreateSessionCliAction` and `ListSessionsCliAction` live beside their session operations, own argument decoding and output, and call `ServerConnection`. Their descriptions also own the usage synopsis. `main.cpp` retains daemon-startup parsing and process-role selection without naming individual tmux operations. Duplicate, late, empty, and unknown action registrations fail before a server request.

`ServerConnection` separates entity-local operation adapters, connection admission/identity, and native frame exchange. `NativeRequestTransport` derives the private endpoint and owns connect, readiness, send, and receive work for one bounded request; it uses the native framing codec without moving socket ownership into the protocol. The first request negotiates the protocol version, payload bound, available operation identities, effects, and required capabilities. Negotiation and execution share one 900-millisecond absolute deadline. Requests reject missing operations and incompatible declarations before effects. Replies pin server identity, including failures; a replacement daemon rejects the old connection before mutation. Closing admission preserves sessions; admitted work can still finish.

`SessionObservation` establishes one atomic session-snapshot and next-event boundary. `ReadSessionEvents` copies the retained suffix immediately; `WaitSessionEvents` owns a bounded pending reply without blocking other server connections. Their native adapters reject a reply whose envelope owner, cursor owner, first sequence, record continuity, or following cursor disagrees with the request. The observer owns each returned cursor. The journal remains bounded derived evidence rather than authoritative server state.

`SessionEventStream` owns one observation cursor, unread records from its current batch, and a cancellation scope on the shared `NativeServerChannel`. Closing the stream interrupts an admitted receive without closing the persistent server or rolling back effects. A discarded journal prefix yields `SessionEventGap` with a replacement `SessionObservation`; the stream adopts that observation's cursor before another read. It serializes cursor consumption. Callback delivery, reconnection, and resumable cursor persistence remain separate work.

Protocol types name their actual lifetime. `AcceptedClientProtocol` retains identification, mode, one-shot command output, terminal attachment, control-mode, and detach wire state for one accepted client while the server event loop owns its socket and the server model owns the corresponding `Client`. Its closed variant gives identifying, awaiting one-shot command, awaiting control startup command, one-shot output, attached terminal, active control mode, draining control output, detaching terminal, and closing transport phases exclusive data. A client cannot re-enter command admission after attachment.

`protocol/tmux/control/` follows the control protocol itself. `control::Channel` owns the transferred input/output descriptors, their nonblocking flags, partial lines, ordered output, and capacity bounds. `control::CommandSequence` owns server-wide guard numbering; `CommandOrigin` and `CommandOutcome` replace boolean protocol switches. `SessionNotificationFeed` translates committed session events from its metadata cursor. `SelectedSessionOutputFeed` owns the selected-session relationship and one raw-output cursor per linked pane. Attachment establishes current tail positions instead of replaying historical raw bytes. Command-result guards acknowledge immediate command handling only. Later pane effects, terminal-state convergence, client composition, and presentation need separate evidence. `StockCommandExchange` retains the shorter reverse state for exactly one outbound command. `StockServerConnection` owns endpoint policy, release evidence, and fresh per-command sockets. Neutral tmux profiles, message contracts, and codecs are shared; role state and lifecycle are not.

Reverse adapters follow the same entity hierarchy as native operations. `ListStockServerSessionNames` owns its fixed command construction, bounded parsing, and registration description under `session/operations/`. The session component adds it through `register_session_stock_server_operations`; the connection composition root consumes the registry into a `StockServerOperationCatalog`. Compatibility reports derive command spellings from that immutable catalog. Raw stock argv exchange remains private, so callers cannot route undeclared effects through a query operation.

The shared reply codec validates server-instance representation, declared error classifications, UTF-8 failure text, and complete error payloads before identity pinning. Successful payloads remain owned bytes for entity-specific decoding. Malformed server metadata produces a protocol failure instead of a fabricated tmux classification.

Public live handles, entity generations, resumable streams, and complete protocol reports remain open. Internal pane-output and session-event cursors are owner-qualified. Oversized encoded arguments return `TmuxError` with operation and observed server context.

## Bindings and documentation

Both bindings link the same C++ connection library. Python releases the GIL for native work and materializes objects after reacquisition. Its native session stream remains synchronous; `AsyncSessionEventStream` adapts each wait through `asyncio.to_thread`, rejects overlapping reads, preserves the C++ cursor, and closes the observer before propagating task cancellation. Node workers keep JavaScript handles on the JavaScript thread; the session stream supplies one promise-backed wait at a time, pull-driven async iteration, `AbortSignal` cancellation, and asynchronous disposal. Identities and revisions use bigint. Raw bytes remain bytes or Buffers. Node translates unsigned integer representations; shared C++ owns window-index and timeout constraints. The Node-API build requires complete C++ callback exception translation, with a controlled compile failure proving the requirement.

`api/exposure.toml` maps named operations and snapshot fields to language interfaces. A shared generator emits C++ assertions and a public catalog borrowing entity-owned descriptions; it requires neither language extension runtime. The installed connection archive contains this catalog. Assertions verify identities, request fields, connection signatures, and value fields. Nanobind inspects the built module for Python stubs. Node declarations and runtime Python briefs use canonical C++ documentation.

Doxygen 1.18 generates HTML/XML with strict warnings and brief-only contracts permitted. Its bundled Clang parser cannot parse the required `std::expected` usage. Doxygen's parser therefore provides navigation; locked Clang 23 supplies callable coverage using actual compiler flags. The inventory includes private functions, operators, templates, callbacks, lambdas, and the compiled exposure file; generated contents participate in cache invalidation. It rejects authored files omitted from compilation. Separate executable entrypoints retain separate coverage even when Clang assigns them the same function identity.

## Compatibility boundaries

`TmuxProtocolProfile` declares the two source-backed Linux x86_64 imsg layouts, frame bounds, descriptor markers, and mandatory version mask. `StockProfileDetector` reports incomplete, matched, ambiguous, or unknown framing evidence. A descriptor marker selects the layout; ordinary headers do not identify it. Detection admits at most 64 KiB before selection, and stock identification expires after 250 milliseconds.

`TmuxCompatibilityPolicy` separates framing from role/mode support. `StockConnectionCompatibility` retains the selected profile, release evidence or uncertainty, support tier, capability fidelity, registered spellings, active quirks, and limitations. A wire match never establishes a release or complete baseline. Accepted-client identification accumulates flag evidence so a later frame cannot erase an admission constraint, and flags cannot change after completion. The current control subset admits single `-C`; it rejects echo-disabled `-CC`, `no-output`, `pause-after`, `wait-exit`, and grouped syntax before effects. Reports declare attachment, notification, buffering, and recovery limits, including connection closure after a metadata observation gap.

A one-shot stock command awaiting its output-stream acknowledgement rejects a second command before that command's effects. Control mode uses its descriptor channel only after the packed startup command completes. Its shared guard counter, 64-KiB line and readiness budgets, 1000-argument limit, 128-command turn limit, and 1-MiB output bound are explicit adapter policy.

Stock tmux 3.4 and 3.7 close an unattached control client after the initial command. The limited C++ subset deliberately keeps that channel open so a later registered command can attach or perform another supported action. Compatibility reports expose this fidelity-changing behavior as `unattached_control_channel_stays_open`; callers can distinguish it from stock behavior.

The current stock paste-buffer subset requires `-b` for every buffer command and an exact `-t %pane` for paste. Automatic buffers, listing, delete-after, custom separators, raw paste, bracketed paste, and copy mode remain unsupported and are named in compatibility reports.

Ordinary interactive clients use the effective global and session `prefix` and `prefix2` values to enter the prefix table. `set-option -g` assigns inherited defaults; `set-option -t target` assigns one session override after live target resolution. Both forms accept only those two names and the declared single-byte key subset. Unset and implicit current-session forms remain unsupported. The prefix table currently contains only `C-b` send-prefix, quote and percent split, `d` detach, and `o` next-pane; configurable key tables and bindings remain unsupported. A matched prefix is retained across reads, an unmatched prefix-table key is consumed after root lookup, effect-free backpressure preserves the table and key for retry, pane targets resolve from current layout state, and detach restores the terminal while preserving the session.

Real unmodified tmux 3.4 and 3.7 clients exercise the declared command subset, including global and targeted prefix assignment, plus guarded control commands, control attachment and switching, no-replay raw pane output, session rename/catalog notifications, and the current interactive multi-pane redraw, selection, attach, resize, input, output, detach, and terminal-restoration path against the C++ daemon. The reverse adapter selects the profile explicitly, obtains release evidence from the connected server, and lists session names through one typed operation. Real mismatched-profile cases fail without stopping the owned server. Full interactive behavior, broader control grammar and notifications, pause/continue, control-mode format subscriptions, older named subsets, broader reverse operations, and language-visible reverse reports remain open. tmux 3.4 remains the first complete-baseline target.

The default build uses Clang 23 with host libstdc++ consistently. The locked libc++ lacks the required `std::move_only_function` facility. Both bindings remain enabled by default. The Linux sanitizer preset instruments native targets, both bindings, nanobind's runtime, and libvterm with ASan/UBSan; recoverable sanitizer reports are disabled. Extension hosts preload the matching shared runtime. Fixtures keep that injection out of unrelated shell programs. Two narrow leak suppressions cover Node OpenSSL initialization and Vitest's external Rolldown DSO, independently reproduced without our addon. First-party memory faults, arithmetic overflow, and leaks remain fatal through controlled probes. Protocol and terminal fuzz targets retain bounded regression inputs and run with leak, address, and undefined-behavior detection active.

passes all configured native, Python, Node Current, and Node LTS tests. Its
